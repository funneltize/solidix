# AGENTS.md - Solidix

## Project goal

Solidix is a port of [Radix UI](https://www.radix-ui.com) to **Solid 2**.

- Maintain **as close to parity as possible** with Radix UI: component set, behavior, accessibility, and public API (adapted to Solid conventions where React and Solid differ).
- Keep the port **clean and efficient**: idiomatic Solid 2 code (fine-grained reactivity, no VDOM thinking), minimal overhead, tree-shakeable primitives.
- Allow **improvements** over Radix where they are clearly better and don't break parity expectations (e.g. simpler Solid-idiomatic APIs, better types, fewer workarounds). Prefer parity when in doubt; document deliberate deviations.

## Tech

- **Solid 2** + TypeScript. Unstyled, accessible primitives - same philosophy as Radix.
- Packages mirror Radix where practical (one primitive per package, e.g. accordion, dialog), plus shared internal utilities.

## Working agreements

- **Parity first**: when porting a primitive, start from the Radix source (behavior, keyboard interaction, ARIA, data attributes, edge cases) and adapt to Solid rather than redesigning.
- **Solid idioms**: signals/memos/effects over hooks emulation; directives and refs where Radix uses refs; no `useEffect`-style ports that fight Solid's reactivity.
- **API mapping**: props stay close to Radix names; convert React-isms (`className` → `class`, `children` → `children` prop/slot, event props to `onX`) per Solid conventions. Keep controlled/uncontrolled patterns and `asChild`/polymorphism equivalents.
- **Accessibility is a feature**: keyboard nav, focus management, ARIA roles/attributes, and reduced-motion handling must be ported and verified, not dropped.
- **Types matter**: full TypeScript types for props, refs, and events; keep them close to Radix's public types.
- **No styling opinions**: primitives ship unstyled (data attributes for styling hooks), same as Radix.
- **Document deviations**: any intentional API/behavior difference from Radix goes in the primitive's README with rationale.
- **No em-dashes**: never write the em-dash character (U+2014) in prose, comments, docs, strings, or tests. Use a spaced hyphen (" - ") or restructure the sentence with commas or a colon.
- **Funnel system**: `@solidix/funnel` is opinionated by design (tokens + themed blocks, the deliberate exception to headless). Its rules live in `packages/solid/funnel/PHILOSOPHY.md` - read that file before touching any funnel token, block, style, test, demo, or doc, and implement from it exactly.

## Repo workflow

- One focused change per commit/PR (e.g. one primitive or one shared utility).
- Add/extend tests for behavior ported from Radix; run the relevant package tests before finishing.
- Any PR touching a publishable package adds a changeset (`pnpm changeset`); `patch` for fixes, `minor` for features (all packages are 0.x, so minor bumps stay non-breaking by convention).
- **Release numbering (0.x)**: versions increment by change size - `minor` moves `0.x` (new primitive, new feature, behavior addition), `patch` moves `0.0.x` (bug fix, types-only, internal refactor with no API change). Never `major` while 0.x; the 1.0 decision is a deliberate release, not a changeset label. To release, run `pnpm version-packages` locally, commit, and push to `main`; the `release` workflow publishes the single `@solidix/solidix` JSR package automatically (OIDC trusted publishing, no token). Actions cannot open PRs in this repo, so there is no Version Packages PR.
- Keep diffs minimal and rooted at the cause; don't refactor unrelated primitives.
- Match existing code style and reuse shared helpers - check sibling primitives before adding new utilities.

## Scaffold conventions (Phase 0 decisions)

- Layout mirrors Radix: `packages/core/*` (framework-agnostic) + `packages/solid/*` (components).
- Package scope is `@solidix/<name>` with no framework infix (deliberate deviation from `@radix-ui/react-*`; this library is Solid-only).
- Every package: `src/index.ts` entry, `lint` / `typecheck` / `build` / `clean` scripts, `tsconfig.json` (extends `@repo/typescript-config/base.json`) + `tsconfig.build.json` for declarations.
- JS builds via `solidix-build` (`@repo/builder`: Vite lib mode + `@solidjs/vite-plugin`, ESM + CJS); types via `tsc -p tsconfig.build.json`.
- Tests live in `test/*.test.tsx` per package and run from the root `vitest run` (jsdom). Use `findBy*` queries - Solid 2 setters flush on microtask, not synchronously.
- Toolchain versions are pinned exactly (Solid 2 is RC-stage); see README. `@repo/smoke` is the private pipeline check - never publish it.
- Package READMEs follow the header template (summary, Solid API mapping + guide links, docs-site route, `Differences from Radix`); task-oriented docs live in `docs/*.md`, single-sourced into the gallery Guides section (`internal/gallery/src/guides.ts` `?raw` imports, rendered by `GuidePage`/`md.tsx`).

## Solid 2 porting patterns (Phase 1 learnings)

- **Context**: a created context is its own provider - render `<Ctx value={...}>`, never `<Ctx.Provider>`. Hooks take no default: `createContext<T>()` then try/catch `ContextNotFoundError` in the `useX` hook to throw Radix's scope error. Context values may be fresh getter objects per render (`{ get open() {...} }`) - Solid has no re-render identity concern.
- **Props**: internal plumbing via `merge`/`omit` helpers; user props via `mergeProps`. Radix `...rest` spread onto the rendered element. `ref` is a plain prop composed with `composeRefs` from `@solidix/compose-refs`.
- **Slots (`asChild`)**: `@solidix/slot` merges parent props onto the single child element imperatively (child wins for class/style/handlers run child-first then parent). Fidelity fixes that must be preserved: document-level capture listeners with a `currentTarget`-proxied event so `flush()` discrete dispatch works; `Reflect.get` without receiver + non-configurable methods returned as-is (avoids proxy invariant violations on synthetic `Event`s).
- **Effects**: `onSettled` for mount work (`onMount` does not exist in Solid 2; cleanup via the returned function - `onCleanup` is forbidden inside `onSettled`); `onCleanup` only in component setup scope. `createEffect` takes TWO functions - `createEffect(compute, (value) => { ...; return cleanup; })` - the single-function form throws. Discrete event dispatch (`flush()` in `callEventHandler`) before assertions on emitted events.
- **DOM attr/style casing**: lowercase `tabindex` (not `tabIndex`) whenever props flow through Slot or merged spreads. Style objects require kebab-case keys (`"outline-color"`, `"padding-bottom"`) - Solid 2 applies each key via `setProperty`, so camelCase multi-word keys are silently ignored, in direct JSX as well as Slot. Read back via camelCase CSSOM properties (`el.style.outlineColor`) as usual.
- **Types**: `JSX` namespace comes from `@solidjs/web`, not `solid-js`. Some aria types are narrower than React's (e.g. `aria-atomic` is string-only) - `Omit` + re-add the prop with normalization when Radix accepts more. Boolean `aria-*` values must be normalized with `ariaBoolean` from `@solidix/primitive` (Solid renders boolean `true` as `""` and drops `false`). Conversely, Solid DOM types are wider than React's (`disabled`/`required` admit `""`, `name`/`form`/`value` admit `false`) - `Omit` + redeclare consumed props with the Radix-narrow type. Bare `aria-hidden` renders as `""` (visible to AT!) - always write `aria-hidden="true"`.
- **Forms**: bubble inputs dispatch `click` + `input`/`change` (not just `click` like Radix) because Solid - unlike React - does not synthesize `onChange` from bubbling clicks. Form events fire only on actual change and mirror the click's bubbling decision; `cancelBubble` (not `isPropagationStopped`, which is React-synthetic-only) detects consumer stops.
- **Children**: dynamic component children arrive as zero-arg thunks (functions!), so never `typeof`-branch values vs render-props naively. Render-prop state (roving tab-stop, presence) is passed as accessors with stable invocation - re-invoking per change remounts children. In Presence, only functions with declared parameters count as render props; component children take the conditional-mount path.
- **Lazy children getters (Wave C)**: compiled JSX children are lazy getters - every raw `props.children` read re-instantiates the whole subtree, and discarded instances still run setup + effects (which crash on detached DOM and, in Solid 2, halt the global reactive queue). Resolve through ONE `children()` memo (it caches); never mix direct reads with memo reads. Never read the getter speculatively (no disposable-root probes - discarded setups fire ref callbacks on orphan elements that disposal never nulls); detect child shape from the resolved value instead (`children()`/`flatten` only unwrap zero-arg thunks, so render props pass through uncalled - see `Presence`). Element children must stay fully lazy (never resolve while unmounted). `Show`'s `fallback` prop instantiates eagerly (it is a plain prop value) while its `children` stay lazy - account for both when reasoning about setup counts.
- **Presence + Portal (Wave C)**: Solid portals resolve to a text marker, so `Presence` must never directly wrap a portal - it cannot resolve or track the portalled content. Put `Presence` _inside_ the portal (`Portal > Presence > Content`); document the leftover markers/wrapper as a deviation in the README.
- **Listener attach timing (Wave C)**: capture/flag listeners that effects depend on (DismissableLayer inside/outside flags vs `FocusScope` autofocus) must attach synchronously in the ref callback, not in an effect - Solid 2 effect order does not guarantee child-before-parent. Conversely, document listeners attached in effects (plus the `pointerdown` listener's `setTimeout(0)` defer, Radix parity) are NOT in place synchronously after render: tests must `flush()` and, for `pointerdown`, await a macrotask before firing.
- **Slot SVG attributes (Wave C)**: SVG IDL properties (`viewBox`, `width`, …) are truthy objects (`SVGAnimated*`), so the child-wins property branch must fall through to the attribute for object-valued IDL. SVG attributes are case-sensitive - keep the authored spelling (`viewBox`), hyphenate only for HTML.
- **Popper defaults (Wave C)**: `side`/`align` defaults (`bottom`/`center`) must apply in `desiredPlacement`, not just the middleware options - raw `undefined` stringifies into the placement (`data-side="undefined"`).
- **No hoisted JSX subtrees under providers (Wave C)**: Solid context flows through setup nesting, not values - a subtree built into a `const` during setup instantiates outside the provider's owner scope and its components miss the context. Build shared subtrees with a render function called inside the (lazy) JSX instead.
- **No identity calls inline in nested JSX (Wave C)**: only top-level return JSX evaluates once - nested levels re-evaluate on every children-getter read. Mint `useId()` (and any identity-bearing value) in setup locals, never inline in nested props, or linkage (`aria-controls`/`id`) desynchronizes across reads.
- **Menu typeahead (Wave C)**: Solid props freeze at setup, so the registered `textValue` can't pick up the post-mount `.textContent` sync - typeahead resolves labels from the live DOM at match time (`getItemTextValue`), with explicit `textValue` props winning.
- **No bare changing-signal reads at setup (Wave C)**: Solid 2 dev wraps components in transparent HMR memos that track bare setup reads as deps - `untrack` does not shield them. A signal that resolves/changes after setup (e.g. a value that is `undefined` until registration) dirties the memo and re-runs setup once per change, leaking orphan instances whose ref callbacks fire on detached elements and whose stale unmount-nulls clobber the live mount's ref. Read changing signals only inside `createEffect`/`createMemo` bodies (own tracking context - respected), JSX binding memos, or event handlers. Initialize prev-value bookkeeping on the effect's first run (dispatching nothing); feed render values like `defaultValue` through JSX bindings. See `SliderBubbleInput`.
- **Forward scope to every scoped child (Wave C)**: scoped packages resolve context through `__scopeX` props, not just ownership - a wrapper that renders a scoped child without forwarding scope sends it to the default context while providers registered under the shadow scope, throwing context-miss errors. Audit every render of a scoped component (including `*Impl` internals like `MenuSubTrigger` → `MenuItemImpl`) for a forwarded scope prop.
- **Composed refs notify on change + null on disposal (Wave C)**: `useComposedRefs` notifies only when the node changes (nested composed callbacks and slot effects push the same node repeatedly; unmount nulls every level) and nulls on owner disposal - Solid never nulls callback refs natively, React does. Assert exact `[el]` / `[el, null]` / `[el, null, el]` sequences in ref tests.
- **Presence render props (Wave C; fixed in Wave D)**: render-prop children stay mounted once detected (Radix `forceMount` parity - the render prop decides what `present: false` looks like); element children unmount when closed. Detection is eager from the children descriptor (no instantiation), so initially-closed render props mount immediately - no deviation. Getter-form children keep lazy detection.
- **Radix test grounding (Wave C)**: port only tests that exist in Radix's suite; never invent Radix-attributed expectations from memory. Genuinely uncovered behavior gets Solidix-authored tests that assert observed Radix-source behavior (e.g. user-`id`-wins-on-content while the trigger keeps the context id; `Tab` prevented inside menus) with a comment citing the source lines.
- **Event handler arrays**: Solid compiles `onClick={[handler, data]}`, so `callEventHandler` must unwrap `[handler, data]` tuples (`packages/solid/primitive/src/dom.ts`).
- **IDs**: `useId` is backed by `createUniqueId` (no React-style prefixing); SSR determinism is best-effort until Solid 2 stable re-verify (Phase 6).
- **Tests**: `flush()` after setter writes made outside `render`'s owner; prefer `findBy*`; `user-event` and `fireEvent` both fine but dispatch through the Slot proxy must not throw on `preventDefault`. Global `ResizeObserver` stub lives in `vitest.setup.ts`.
- **Disposal writes**: ref callbacks fire with `null` during disposal (an owned scope) and effect cleanups also run owned - signal writes there throw `REACTIVE_WRITE_IN_OWNED_SCOPE` and halt reactivity. Signals written from refs or cleanups (collection element/registry bookkeeping) take `createSignal(..., { ownedWrite: true })`. Teardown bookkeeping must not read signals a ref detach may already have nulled - capture the value in the effect closure instead.
- **Test reactivity**: signal reads in plain test helpers are one-shot; to drive prop updates, pass the read as a component prop (`<Ui src={src()} />`) - Solid compiles component props to reactive getters. `flush` is exported from `solid-js`, not `@solidjs/testing-library`.
- **Microtask batching**: Solid 2 defers even read-your-writes to microtask - back-to-back sync events (drag down/move/up) read stale values without a drain. Gesture handlers whose steps read prior writes must `flush()` after mutating (slider `updateValues`), mirroring Radix-under-`act()` sync semantics. `flush()` in event handlers is fine (precedent: `dispatchDiscreteCustomEvent`); never in effects/actions (diagnosed no-ops/throws).
- **Solid 2 RC API gaps**: no `Suspense`/`createResource`/`startTransition` in this RC - React-concurrency tests (Suspense/Activity/transitions) cannot be ported; cover the underlying behavior (mount/unmount/reorder) with signals + `<For>` instead. Re-verified at rc.16: new `createDeferred` is an async-data memo with `isPending`, not transition scheduling, so async-apply coverage via microtask/timeout tests stands.
- **Ref set ≠ connected (Wave D)**: Solid calls `ref` at element creation, before portal insertion adopts the node, and slotted children resolve later still - a set ref does not imply a connected node. Before adoption a template-cloned node's `ownerDocument` can be a detached template-contents document with null `body`. Document-dependent setup (`ownerDocument` listeners, `body` locks, `hideOthers`, Slot delegated listeners) must go through `afterConnected` (`@solidix/compose-refs`: sync fast-path when connected, else a `MutationObserver` waits for the insertion mutation itself) and re-read `ownerDocument` after connecting. Keep insertion-agnostic work (layer registration) synchronous; the body-lock applied-flag is module-level because the restoring layer usually differs from the applying one. Tests asserting lock state, outside dismissal, or slotted delegated handlers must settle first (`findBy*`/`vi.waitFor`), and `hideOthers` no-ops on unusable parents instead of crashing.
- **Sync asserts after interactions (Wave D)**: Solid 2 flushes click→state→DOM asynchronously - no sync `getBy*`/style assertions after `fireEvent`; always `await findBy*`/`vi.waitFor` (popover idiom). `id={false}` normalizes to `undefined` internally; `aria-describedby` concatenation takes `unknown[]`; CSS-in-JS keys are kebab-case (`"pointer-events"`).
- **Refs fire before children exist (Wave D)**: ref-time DOM reads (`textContent`, `<option>` matching) see empty state - children/text insert after. Defer dependent work to effects or `onSettled` (select item text re-sync; bubble-input post-insertion value effect).
- **Effect cleanup discipline (Wave D)**: `onCleanup` inside two-arg effect callbacks does not scope to the effect - return the cleanup function from the callback instead (collection precedent). Callbacks must return cleanup-or-`undefined`: an expression body returning a value (setter result, `requestAnimationFrame` id) halts reactivity.
- **Uncontrolled `onChange` is async (Wave D)**: `useControllableState` fires uncontrolled `onChange` from an effect - wrap the interaction in `flush()` before asserting the handler call.
- **Compose consumer handlers via wrapper (Wave D)**: pass `(event) => callEventHandler(rest.onX, event)` (typed with the Solid event) as the first arg to `composeEventHandlers`, never `rest.onX` directly - Solid handler props admit `[handler, data]` tuples.
- **Collection ItemSlot getters (Wave D)**: legacy `ItemSlot` data values may be getters, resolved and tracked in the registration effect - for data known only after mount (select `textValue`). Plain values behave exactly as before.
- **Solid 2 RC API notes (Wave D)**: `omit(props, ...keys)` is variadic (no array form); no `Key` (single-item `For` recreates on value change); no `startTransition` (cover async-apply with microtask/timeout tests). `Show keyed` children must declare a parameter.
- **jsdom `scrollIntoView` (Wave D)**: stubbed as a no-op in `vitest.setup.ts` (Radix does the same) - focus management calls it unconditionally.
- **Delivering `ResizeObserver` stubs (Wave D)**: the shared setup stub never delivers observations; tests asserting resize-driven rendering (scroll-area corner, navigation-menu indicator) install a delivering observer with `vi.stubGlobal` + `unstubAllGlobals` (Radix's setup fires on `observe`).
- **Presence ignores Solid-only markers (Wave D)**: child resolution skips comment anchors (`Show`/keyed branches) and empty text nodes (`Portal` placeholders) - React has no equivalent artifacts and Radix tolerates null renders. Non-empty text and multiple elements still throw; the tracked node feeds exit animations only.
- **`asChild` viewport portals content (Wave D)**: `Slot` moves siblings into the slotted target in a deferred effect, so sibling-rendered proxied content would leave `Presence` resolving two top-level elements pre-move (breaking exit tracking). Navigation-menu portals its content list into the consumer's element instead (identical rendered DOM); a `Slottable` render fn cannot substitute because the registry fills only once mount effects flush and an initially-empty `For` has no anchor there.
- **Style objects are kebab-case + object-only (Wave D)**: Solid does not convert camelCase style keys (React does) and parts that merge base styles cannot spread string styles - tests use `style={{ "outline-color": … }}` and part props narrow `style` to `JSX.CSSProperties` (select/navigation-menu precedent).
- **Meta-package (Wave D/E)**: `solidix` (`packages/solid/solidix`) re-exports the 30 component primitives as namespaces (`export * as Dialog`), mirroring `radix-ui`; internals stay separate subpath imports. Adding a primitive means adding its dependency, namespace line, and test-table row together.
- **JSR packaging**: the registry artifact is one JSR package, `@solidix/solidix`, assembled from every workspace `dist/` by `scripts/jsr-publish.mjs` (one subpath export per package, umbrella at `.`). Never publish raw `.tsx` - Solid needs its compiler, and JSR's TSX transpile would emit a broken react-jsx transform. The staged package must stay verifiable with `pnpm release:dry-run`; funnel/motion CSS cannot ship on JSR (JS modules only) and is documented as vendored copies.
